# 拾图 · 本地图片分析

English documentation: [README.en.md](README.en.md). Release notes: [中文](release/RELEASE-NOTES.md) · [English](release/RELEASE-NOTES.en-US.md).

为这台 Mac 制作的个人工具。提供“增强模型”“ChatGPT 直连（Codex CLI）”和“自定义 API（OpenAI 兼容）”三种分析方式：增强模型使用本机 Qwen3-VL 8B 与 Pinterest 设计图板训练的 LoRA，ChatGPT 直连使用本机已登录的 Codex CLI 处理图片并把结构化结果回传拾图；自定义 API 可填写自己的视觉模型接口。

## 打开

双击本目录的 `拾图.app`。应用已包含启动所需的程序和界面；它会按需启动本地服务。

首次打开时，拾图会在本机读取 Apple Silicon/Intel 架构、统一内存、可用磁盘和 macOS 版本，并给出本地模型推荐。模型清单保存在 model-manifest.json，同时记录已验证的“Qwen3-VL 8B + 拾图 Pinterest LoRA”和轻量、高质量候选。当前发布包不内置模型，也不会把候选模型误标成已经可以一键下载；对应来源和接入状态见 MODEL-DOWNLOADS.md。

项目源码与唯一的完整应用包都位于 `~/Library/CloudStorage/OneDrive-个人/codex/拾图`。启动台的 `~/Applications/拾图.app` 是打开这份应用的小启动器，不包含另一套图片分析程序。

增强模型运行环境、配对配置、分析历史和日志位置：`~/Library/Application Support/拾图`。`paths.json` 记录此位置。模型不会跟随 OneDrive 同步。该配置仅适用于这台 Mac，同步到另一台电脑不等于已经安装模型。

- 打开图片：菜单“拾图 → 打开图片…”（⌘O），支持 macOS 可解码的图片。
- 剪贴板图片：先复制图片，再点击“分析剪贴板图片”。
- 跨浏览器/软件：按 **⌃⌥I**，仅框选目标图片。按 Esc 取消。第一次需要由你在 macOS 系统设置中允许拾图录制屏幕。
- Finder：图片右键 → 服务 → **用拾图分析图片**。系统服务注册后才会出现；可能需要在系统设置的键盘快捷键/服务中启用。
- Chrome：加载本目录 `extension` 文件夹后，在图片上右键可选择“增强模型”或“ChatGPT 直连”；在侧栏中也可切换到“自定义 API”。支持 Chrome Side Panel：右键分析会在浏览器侧栏打开拾图，分析结果和最近记录不会遮挡网页；点击工具栏中的拾图图标也可打开侧栏。旧版浏览器不支持 Side Panel 时，会回退为当前网页上的可拖动浮窗。

结果页有“返回主页”按钮。每项都可单独复制；“复制提示词”仅复制整合后的生图提示词；“复制全部模块”包含全部八项。左侧历史栏保留最近 10 条完整文字结果，点选即可重新查看。

选择“ChatGPT 直连（Codex CLI）”时，拾图把当前图片交给本机的 `codex exec --image`，要求它严格返回八个中文 JSON 模块，再把结果显示在拾图页面并写入最近记录。它不需要配置 OpenAI API Key，但需要单独安装 Codex CLI 并完成 `codex login`；安装 ChatGPT 桌面 App 本身不会自动安装或登录 CLI。首次设置页会显示“未安装 / 未登录 / 已就绪”，已安装 CLI 时点击“打开 Codex 登录”会在 Terminal 中启动官方登录流程，登录完成后点击“重新检测”。如果 CLI 未安装，按钮会打开官方安装说明。CLI 暂不可用时，结果页仍保留复制图片、详细要求和页面链接到 ChatGPT 网页的备用入口。

“自定义 API（OpenAI 兼容）”要求接口支持 Chat Completions、图片输入和 JSON 输出。选择后填写完整的接口地址、视觉模型名称和 API Key，再点击“保存 API 设置”。Key 只保存在这台 Mac 的 `~/Library/Application Support/拾图/config.json`，该文件权限为仅当前用户可读写；界面、历史记录和本机接口响应都不会回显 Key。留空保存不会覆盖原 Key，点“清除已保存的 Key”可删除它。

“本地增强模型”使用 Qwen3-VL 8B 与来自该 Pinterest 图板的 LoRA 适配器。当前训练集为 23 张人工标注图片，另有 3 张本地验证图；用户提供的 Lacoste 海报没有用于训练。它是小样本实验，可能更擅长区分摄影主体与平面背景，但仍可能漏掉姿势或场景细节，结果需要核对。增强模式无需 API，图片留在本机；首次加载会占用较多统一内存，连续空闲约三分钟后自动退出模型进程。旧版本保存的“本地模型”或 API 模式偏好会自动忽略，并默认使用增强模型。

训练图片、基座模型和训练记录保存在日常 coding 工作区的 shitu-training 文件夹。应用数据目录保存独立 MLX Python 运行环境、适配器和基座模型的 APFS 克隆；训练文件夹中的原始基座模型仍保留，应用使用自己的模型路径，避免依赖文稿目录权限。两个副本共享 APFS 底层数据块，未重新下载模型。不要删除应用数据目录中的 mlx-qwen3-vl 文件夹，否则增强模式无法启动。

## Chrome 开发版安装

1. 打开 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目的 `extension` 文件夹。
4. 回到图片页面。已经打开的页面无需刷新即可右键触发。

扩展只申请当前标签页、右键菜单、按需脚本注入和本机服务访问权限，没有所有网站的持久读取权限。右键目标的图源地址用于读取该图；读取失败时，只有能确认图片位置且图片完整可见时才使用截图裁切。多张同源图位置有歧义、嵌套页面或受限页面会提示改用框选，避免分析错图。浏览器内部页面无法注入浮窗。

Safari 原生右键扩展尚未打包。Safari、Firefox 以及其他软件目前使用框选浮窗；它覆盖在原窗口上方，不属于网页内部。Chrome 以外的扩展兼容性没有验证。

## 运行与隐私

- “增强模型”在本机运行，无 API Key、无按次费用；模型使用 MLX，并按需启动。“ChatGPT 直连（Codex CLI）”通过本机已登录的 Codex CLI 发送当前选中的图片并接收结果，图片只会发送给 Codex CLI 使用的 OpenAI 分析服务；CLI 账户的额度和网络连接仍会影响结果。“自定义 API”会将当前选中的图片和分析要求发送到你填写的接口地址。
- 分析服务：127.0.0.1:19428；MLX：127.0.0.1:19429。均不向局域网开放。新版使用独立端口，避免误连仍在运行的旧版服务。
- 首次准备运行器和模型需要网络；网页原图获取需要访问原图站点。增强模式只把当前选中的图片发送到本机回环服务；ChatGPT 直连会通过 Codex CLI 将当前选中的图片发送给 OpenAI 进行分析。Codex CLI 的登录凭据保存在用户自己的 Codex 配置中，拾图不会读取或记录其中的令牌。
- 图片分析前压缩至最长边 1280 像素；透明区域使用白底。截图先本地裁切，整页截图不会交给模型。
- 不保存输入图片、不记录浏览页面地址。最近 10 条分析的八个文字模块保存在 `~/Library/Application Support/拾图/history.json`，Mac App 和 Chrome 扩展共用；新结果会覆盖最旧记录。文件使用 macOS 本机文件权限保护。服务内的分析任务状态仍只保留在内存中，约十分钟后清理。
- 本机配对令牌和自定义 API Key 位于应用数据目录的 `config.json`。`extension/config.js` 是由构建脚本生成并被 Git 忽略的本机配对文件；不要把它提交到仓库，也不要把个人构建包公开分享。正式公开分发前应改为每台设备首次配对。
- 模型完成分析后保留约三分钟，然后释放。首次分析通常比连续分析慢。

镜头焦段、光圈及确切材质不是从单张图就能确定的事实。工具要求模型明确推测，结果仍需人工核对。

## 维护

- `Sources/main.swift`：原生浮窗、菜单、截图、Finder 服务。
- `launchpad/`：启动台小启动器与图标的源文件；它打开 OneDrive 中的唯一应用包。
- `server.py`：本机分析接口与本地模型服务管理。增强模型另用应用数据目录中的 MLX Python 环境。
- `web/`：三种分析方式共用的分析界面。
- `extension/`：Chrome 扩展。
- 本机数据目录的 `runtime/`、`models/`：固定版本运行器和模型。
- 本机数据目录的 `logs/`：启动及下载日志，不保存用户图像。
- `tests/test_bridge.py`：本机接口授权、来源验证与单图调度检查。

关闭拾图后，在 Chrome 中移除扩展，将此应用文件夹及 `~/Library/Application Support/拾图` 移至废纸篓可回收空间。旧版若曾将 API Key 存入 macOS 钥匙串，新版不再读取或使用它，但会保留原钥匙串项目。
